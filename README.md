# loch.js — cross-platform POC

One TypeScript / Three.js frontend, built as an offline PWA with Vite and packaged for Windows, Linux and macOS with Tauri 2. LOX, Survex `.3d`, and Compass `.plt` files are parsed locally in the browser; no upload or backend. Drag/drop or open a supported file; orbit with left drag / one finger, pan with right drag / two fingers, zoom with wheel / pinch. Use the menu controls and altitude legend. Includes a generated native-format demo cave.

The startup demo keeps the menu bar expanded. Controls live in a dock centred at the bottom of the screen: the menu button, Open file, Set rotation centre, My location (GPS), Entrances with their label button, and the station label button. The menu button opens the **File**, **Scene**, **View**, and **Rendering** menus just above the dock (their dropdowns open upwards) together with the bottom status line. The menu starts closed; the status line also appears on its own while a file loads or when loading fails. The red bounding box (Scene → Visibility → Bounding box) appears for 3 seconds after a model opens and after each projection change, then hides. Use **File → Open…**, **Scene → Visibility → Bounding box / Centreline / Walls / Surface / Indicators**, **Scene → Centreline → Surface / Underground / Color / Splay / Duplicate / Stations / Label**, **Scene → Walls → Culling / Texture walls**, **Scene → Surface → Image overlay / Transparency / Opacity**, **View → Autorotate / Perspective / Lock tilt / Set rotation centre / My location (GPS) / Plan / Profile / Fit**, and **Rendering → Light / Detail / Full screen**. Visibility, Centreline, Walls, Surface, and Light are expandable groups. Perspective toggles between perspective and orthographic projection without rotating the camera, changing its target, or changing tilt lock. Scale at the camera target is preserved: perspective always uses its natural 45° field of view and carries the scale in the camera distance, while the orthographic camera moves back along its line of sight behind the whole model so nothing is cut off, however far you zoom out. Plan looks down the Z axis; Profile is a side view with Z vertical. Both enable Lock tilt automatically. Fit recenters and fits the model while preserving tilt, rotation, and tilt lock. Lock tilt holds the current inclination while allowing heading rotation, pan, and zoom; uncheck it to tilt freely. **Set rotation centre** (View menu, or the target button in the dock) turns the next click or tap on the model into the rotation centre: the nearest visible wall, surface point, or centreline shot within a few pixels under the cursor is picked, and the view pans smoothly so that point sits in the middle of the screen. Orientation, distance, projection, and tilt lock are kept, and a short-lived ring marks the new centre. Dragging while the mode is active does nothing; clicking empty space keeps the mode open, and Esc or the button cancels it. **My location (GPS)** (View menu, or the pin button in the dock) shows the device position on models stored in S-JTSK (Therion `cs ijtsk`, identical to EPSG:5514 Krovak East North). The browser's WGS 84 fix is converted in the app with the Slovak EPSG "S-JTSK to WGS 84 (4)" datum shift (about 1 m) and the Krovak projection, then placed on the LOX surface terrain at that point; outside the surface it uses the GPS height. A blue dot marks the position (pinned to the screen edge when off-screen), a translucent disc shows the reported accuracy, and a line at the bottom gives accuracy, height and x/y in the model's system (cs ijtsk), or the distance when you are outside the model. The first fix pans the view to you when you are within 1 km of the model. Models in local coordinates are reported as not georeferenced. Location needs HTTPS (the GitHub Pages build or the installed PWA) and the browser's permission. Texture walls is off by default; enabling it replaces wall depth colors with a repeating limestone texture and subtle surface relief. Texture mapping uses model coordinates, so LOX files need no UV coordinates or extra full-mesh normal arrays. The same stone appearance applies to Automatic point previews and refined views, and the texture is included in the offline PWA cache. Centreline colors use altitude by default. The shared color scale uses only underground centreline and splay shots plus cave wall vertices; surface shots, terrain, and isolated stations do not expand its range. Model fitting still includes all geometry. See [texture asset and generation prompt](src/assets/README.md). Culling is off by default; enabling it hides back-facing triangles and corresponding preview points, using the source triangle winding. Rendering → Light provides Static (default), Follow camera, and Headlight modes. Static uses world-relative Bearing (0–360°, clockwise from north/+Y) and Clino (−90° below to +90° above). Follow camera uses camera-relative offsets: 0°/0° places the directional light at the camera, positive bearing rotates toward camera-right, and positive clino rotates toward camera-up. Each directional mode remembers its own angles during the session: Static starts at 27°/53°, Follow camera at 0°/0°. Headlight replaces directional and hemisphere lighting with a camera-mounted soft spotlight, brightest in the centre and fading toward the screen edges. Its cone adapts to projection, zoom, and viewport shape, with brightness independent of model distance. Bearing/clino are disabled in Headlight and restored when returning to a directional mode. Scene visibility, culling, and light choices carry over when opening another file. Click `loch.js` for build information.

The loaded project title appears at the upper left and remains visible with the menu collapsed. Both loaders use the first nonempty LOX survey title, then the survey name or filename if no title is stored. Long titles are shortened visually to fit the screen.

**Dock shortcuts** mirror menu controls and stay in sync with them. The Ω button shows cave entrances (Scene → Centreline → Stations → Entrance) as a white omega with a thin black outline. Entrance symbols are sized by zoom, 30 % with the whole model in view up to 100 % at a 100 m scale bar. The label button next to it (a small Ω with index 1) cycles entrance labels: names, then altitudes, then off. Entrance names come from the station comment, which Therion exports use for the cave name, falling back to the survey name. The station label button (a small + with index 1) shows all survey stations (Stations → All) with numbers, then altitudes, then number@survey, and the fourth click hides the stations again. A small letter in the corner of a label button shows the active label (N name, m altitude, # number, S survey); clicking a label button while its symbols are hidden turns them on first. Entrance labels are set separately from station labels (Stations → Entrance label).

**Field objects** record what you find in the field. The pin-with-plus button in the dock, right of the folder, opens a form that starts reading the device position at once (GPS, converted to S-JTSK like My location, with the terrain height from the model surface when available). **Pick in model** hides the form so you can tap any wall, surface point or centreline shot instead; the point keeps the model's coordinates, and **Use GPS** switches back. Diacritics never enter the app: they are removed from the name, note and team as you type. On saving, the name becomes a Therion survey id, lower case with underscores, followed by the actual save date and time from the device clock (`Zavrt pod hrebenom` saved 22.10.2026 12:25:48 → `zavrt_pod_hrebenom_26-10-22_12-25-48`). Add a note and one or more photos (on phones, Add photo offers the camera or the photo library). Objects are stored on the device (IndexedDB) and survive reloads and offline use; the browser is asked to keep this storage persistent. On S-JTSK models they appear as orange diamonds with their names (Scene → Visibility → Field objects). **File → Field objects…** lists them; tap one (or Open) to view and edit its name, note, photos and position (the save time in its id stays), tap a photo to see it full size with ‹ › between photos, delete with Delete tapped twice, and **Export to Therion** saves `j_mobil.zip` exactly like the GPX → Therion j_mobil generator: `j_mobil/<id>/<id>_th.th` (entrance station `gps_mob` fixed in the model's coordinate system, `cs ijtsk` x y with Bpv height, note as comment, Zameral as team), `thconfig_200.th` from the same template, `_data/desktop.ini` with the photos, plus `j_mobil.th` and `thconfig.th`. Objects without a position are left out of the export.

**SHP layers** add point data from GIS. Open a `.shp` with the dock's open button, File → Open…, or drag and drop, together with its `.dbf` (point names), `.prj` and `.cpg` when you have them. Points, multipoints, and the vertices of lines and polygons (2D, Z or M) become coloured dots pinned to the model's terrain (the LOX surface height at each point; the file's Z or the model centre only where no surface exists). Coordinates are used as they are when in S-JTSK like the model (cs ijtsk / EPSG:5514); positive JTSK Y/X are flipped and WGS 84 (from the .prj or by value range) is converted. Names come from a NAME/NAZOV/ID-like field. The dock's entrance buttons also drive field objects and SHP points: Ω shows or hides all three, and its label button switches names, altitudes (terrain height) and no labels for all of them; importing a layer or saving an object turns Ω on. SHP labels that would overlap are skipped. Entrance symbols, field objects and SHP dots share one size that follows the zoom: 30 % when the whole model fills the view, 100 % from a 100 m scale bar on, smoothly (logarithmically) in between; models smaller than that always show full size. Layers are kept on the device; Scene → Visibility → SHP layers hides them. **File → SHP files…** picks a layer, steps through its points (‹ ›, or the point list), shows each point's x/y, terrain height, file Z and all .dbf attributes, marks it with a white ring, and **Show in model** centres it (zooming in to a 100 m scale if needed); **Remove layer** (tap twice) deletes the layer. Positions taken in the app (GPS or picked in the model) are rounded to whole metres.

**Indicators** starts enabled under Scene → Visibility and controls the project title, altitude color legend, compass, tilt indicator, and horizontal scale bar together. They sit in one translucent row centred at the top of the screen: compass, tilt, scale bar, and a vertical altitude legend (highest at the top). The project title stays at the upper left on wide screens and moves under the row on narrow ones. Indicator panels use translucent backgrounds; bearing runs clockwise from north (+Y), and tilt is 0° horizontal, +90° up, or −90° down. Click the compass to face north with the heading held (rotation keeps only tilt, pan and zoom); click again to return to the previous heading. The third indicator switches perspective and orthographic projection (a box drawn in perspective or in parallel projection, labelled Persp or Ortho). Click the tilt indicator for a level side view with tilt locked; click again to return to the previous tilt and tilt-lock setting. Each toggle restores only its own angle, so both can be combined, and Plan, Profile or Fit clears them. The scale bar follows zoom and projection changes, and uses a rounded metric distance measured in the plane through the camera target for perspective views. Reopening the menu restores the bottom status line; collapsing it hides the line and gives that space back to the model.

**Centreline** has separate Surface, Underground, Splay, and Duplicate toggles; only Underground is enabled by default, so surface, splay and duplicate shots start hidden. The Visibility → Centreline checkbox still hides or shows the entire centreline. Color defaults to Altitude; Default uses pure white for ordinary underground and duplicate shots. Surface shots stay gray in either color mode. Splays use half saturation and lower lightness in Altitude mode, and muted gray in Default mode. Duplicate shots otherwise use the same colors as ordinary underground shots. Shots with multiple flags respect each applicable visibility filter; LOX shots marked not visible remain hidden. Both loaders preserve the shot types, and these controls retain their choices when another file is opened.

**Surface** displays terrain grids and their embedded JPEG/PNG map images from the LOX file, positioned using their own world calibrations. It starts visible, with Transparency enabled and Opacity at **50%**, matching [Loch’s defaults](https://github.com/therion/therion/blob/master/loch/lxSetup.cxx). Image overlay starts enabled. Turning it off replaces the map image with a 100% white terrain material shaded by the current scene lights, including Follow camera and Headlight. Turning it back on restores the image without reloading it. The Opacity slider appears when Transparency is enabled; turning transparency off makes the terrain opaque and preserves the slider value. These choices carry over to the next model. Terrain without an embedded image is white, and files without terrain display the cave as before. Terrain is included in the model’s bounding box and initial fit; cave depth colors retain their original cave altitude range. Both file loaders support surfaces, and Automatic detail composites transparent terrain once after the opaque wall batches finish.

**Stations** under Scene → Centreline is an expandable group with Entrance, Fixed, Continuation, and All, all unchecked by default. Entrance shows a black omega symbol matching the app icon in a white circle, Fixed a red filled triangle, Continuation a question mark, and All the small white station dots. Special symbols are centred on their stations; if several selected types apply, Entrance takes priority over Fixed, then Continuation. Surface, entrance, and fixed stations remain visible when their surface/underground centreline filter is off. Ordinary underground stations follow the Underground filter. **Label** defaults to **(None)**; choose **Number** for the stored station name, **Short** for `name@survey`, **Full** for `name@survey.parent.root`, **Altitude** for the original elevation in metres, or **Comments** for station comments (LOX and Compass). Labels use a single screen overlay without depth testing. Overlapping labels are skipped, considering commented stations first; zooming in reveals more labels. Long labels are shortened to fit. Labels follow the camera. Temporary splay endpoints (`.` and `-`) have neither dots nor labels, even when Splay lines are enabled. Clearing all station selections or turning off master Centreline visibility hides station markers and labels. Both loaders preserve station names and survey hierarchies, and choices carry over between files.

**Autorotate** starts off and can be toggled from View → Autorotate. It turns around the current orbit centre once every **15 seconds**, preserving tilt and distance, with speed measured from elapsed time rather than frame count. Start, stop, and start again within one second, measured from the first start, to reverse direction. The chosen direction is remembered for later starts and app reloads (rotation still starts paused). Dragging temporarily pauses the automatic turn. Loading/preparing a large file and hidden browser tabs also pause it; rotation resumes afterward. Pausing lets Automatic detail refine the stationary view as usual. While autorotation is enabled and the page is visible, the app requests a [screen wake lock](https://www.w3.org/TR/screen-wake-lock/) to prevent automatic screen sleep/locking where supported. Pausing or leaving the page releases it; returning to the page requests it again if autorotation remains enabled.

## Development

Requires Node.js 22+ and npm. `npm install && npm test && npm run dev`. Production site: `npm run build && npm run preview`. Serve the `dist` directory over HTTPS for PWA installation (localhost is also accepted). After first successful load, install the app via your browser and reopen offline.

Desktop: install Rust, platform [Tauri 2 prerequisites](https://v2.tauri.app/start/prerequisites/), and `npm install`. Run `npm run tauri dev`; bundle with `npm run tauri build`. Linux AppImage/DEB requires WebKitGTK 4.1 etc. Windows packages need WebView2 (provided or installed by Windows/installer). macOS builds need Xcode command-line tools.

Desktop builds use their bundled frontend without a PWA service worker. On launch, the native app removes any service workers and cached pages left by older desktop versions and reloads once if needed. Updating or reinstalling therefore recovers from the old desktop PWA cache automatically. Browser and Android PWA builds retain offline caching.

## CI and publishing

`.github/workflows/ci.yml` tests/builds web and the three desktop systems on PRs and pushes. `main` pushes deploy GitHub Pages (enable **Settings → Pages → Source: GitHub Actions**); `v*` tags attach `.exe`, `.msi`, `.deb`, `.AppImage`, `.dmg` release assets. The macOS `.app` is delivered inside the DMG and stored as a workflow artifact. Unsigned desktop binaries may trigger operating-system security prompts. GitHub Pages path is inferred from `GITHUB_REPOSITORY`.

CI identifies builds as `<last-version>-<short-commit>`, using the latest reachable `v*` version tag without its `v` prefix and seven commit characters (for example `0.1-abcdef1`). Before the first version tag, the package version is used. Installer filenames end in that build ID, for example `loch.js_0.1.0_x64-setup_0.1-abcdef1.exe`. Artifact archives are named `desktop-<platform>-<build-id>` and `web-pwa-<build-id>`. Compare the short commit with the About dialog opened by clicking `loch.js`.

## LOX notes and limitations

The LOX parser reads Therion survey metadata, stations, centreline shots, indexed cave walls, surface terrain, and surface imagery. Source coordinates are locally recentered for floating-point precision. Small LOX walls use shared indexed vertex normals within each scrap; separate scraps do not share normals.

Survex `.3d` imports support [versions 3–7](https://survex.com/docs/3dformat-old.htm) and [version 8](https://survex.com/docs/3dformat.htm), including compressed station names, survey hierarchy, surface/duplicate/splay flags, and centimetre-to-metre coordinate conversion. [Compass `.plt`](https://www.fountainware.com/compass/HTML_Help/Compass_Viewer/plotfileformat.htm) imports convert North/East/Up coordinates in feet to East/North/Up metres, preserve station and survey names, and keep disconnected traverses separate. As in Survex’s Compass reader, plot-excluded `P`/lowercase `d` legs are classified as surface, `L` as duplicate, and `S` as splay. Feature records are skipped. Both imports provide centreline, station labels, and LRUD walls using the existing controls.

**LRUD walls** are generated when loading usable passage dimensions from LOX, Survex, or Compass. LOX section types (oval, square, diamond, tunnel), vertical thresholds, and no-LRUD flags are respected; stored scraps are preserved alongside explicitly requested LRUD walls. Survex passage boundaries and Compass move commands keep separate passages disconnected. Sparse Survex cross-sections interpolate along intervening underground survey legs. Surface, splay, duplicate, and hidden legs do not generate walls. Negative/missing dimensions stop at the station axis; wholly missing or zero-size cross-sections produce no walls. Shared profiles are welded around bends, with caps at passage ends and stable profiles for vertical shafts. Generated wall extents contribute to fitting and the underground color scale. The existing Walls visibility, culling, texturing, and lighting controls apply. These walls approximate passage tubes; complex branch junctions can overlap.

LOX files larger than 32 MiB use an experimental full-detail loader: a worker reads at most 8 MiB at a time, scans the bounds, and transfers batches of at most 65,536 triangles. It never reads the whole file into one buffer or expands large meshes into JavaScript point/triangle objects. Source triangle order and winding are preserved. Large walls use GPU flat shading and altitude coloring to avoid normal/color arrays; small files retain their existing shading. The bounds and centreline remain visible during loading, with the walls shown after geometry preparation and upload. Status progress continues through geometry preparation and GPU upload with batch percentages, then shows animated indicators for shader compilation and the first wall render. Loading finishes only when that GPU render completes. Opening another file cancels the current load and preparation.

**Rendering → Detail → Automatic** uses shaded point samples and a 262,144-triangle budget while moving. Point normals come from at most 512 sampled faces per batch, with altitude colors and the scene’s hemisphere/directional lighting; no full-mesh normal calculation is needed. After the camera stops, every visible triangle batch is progressively drawn into a cached color/depth image; the moving-preview budget does not limit the finished stationary view. Each batch's GPU buffers are released after drawing, while the full source geometry remains in memory. Moving the camera resets refinement. Loading and refinement show a background progress bar behind the status text. **Full detail** is the default and attempts to draw every triangle directly. `domica-10cm.lox` has 27,647,432 triangles and needs about 949 MiB for positions alone; direct full-detail rendering also needs a GPU copy and can be very slow on software graphics or devices with limited GPU memory.

Generated sample: `python scripts/generate-sample.py` — synthetic geometry in genuine LOX record layout, not a model exported by Therion. Test against actual Therion exports before production. No cross-platform runtime/browser checks, notarization, signing or release publication can be claimed until GitHub runners are executed.

**Reproducibility:** The package-lock could not be generated in the offline build environment. CI currently runs `npm install`; commit a lockfile and change this to `npm ci` once registry access is available.
