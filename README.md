# loch.js — cross-platform POC

One TypeScript / Three.js frontend, built as an offline PWA with Vite and packaged for Windows, Linux and macOS with Tauri 2. LOX files are parsed locally in the browser; no upload or backend. Drag/drop or open a `.lox` file; orbit with left drag / one finger, pan with right drag / two fingers, zoom with wheel / pinch. Use the menu controls and altitude legend. Includes a generated native-format demo cave.

The startup demo keeps the menu bar expanded. Opening your own file collapses the entire bar to a three-bar button and hides the bottom status line; click it to restore the horizontal **File**, **Scene**, **View**, and **Rendering** menus. Use **File → Open…**, **Scene → Visibility → Bounding box / Centreline / Walls / Surface / Indicators**, **Scene → Centreline → Surface / Underground / Color / Splay / Duplicate**, **Scene → Walls → Culling / Texture walls**, **Scene → Surface → Image overlay / Transparency / Opacity**, **View → Walker / Autorotate / Perspective / Lock tilt / Plan / Profile / Fit**, and **Rendering → Light / Detail / Full screen**. Visibility, Centreline, Walls, Surface, and Light are expandable groups. Perspective toggles between perspective and orthographic projection without moving or rotating the camera, changing its target, or changing tilt lock. Scale at the camera target is preserved. Plan looks down the Z axis; Profile is a side view with Z vertical. Both enable Lock tilt automatically. Fit recenters and fits the model while preserving tilt, rotation, and tilt lock. Lock tilt holds the current inclination while allowing heading rotation, pan, and zoom; uncheck it to tilt freely. Texture walls is off by default; enabling it replaces wall depth colors with a repeating limestone texture and subtle surface relief. Texture mapping uses model coordinates, so LOX files need no UV coordinates or extra full-mesh normal arrays. The same stone appearance applies to Automatic point previews and refined views, and the texture is included in the offline PWA cache. Centreline colors use altitude by default. See [texture asset and generation prompt](src/assets/README.md). Culling is off by default; enabling it hides back-facing triangles and corresponding preview points, using the source triangle winding. Rendering → Light provides Static (default), Follow camera, and Headlight modes. Static uses world-relative Bearing (0–360°, clockwise from north/+Y) and Clino (−90° below to +90° above). Follow camera uses camera-relative offsets: 0°/0° places the directional light at the camera, positive bearing rotates toward camera-right, and positive clino rotates toward camera-up. Each directional mode remembers its own angles during the session: Static starts at 27°/53°, Follow camera at 0°/0°. Headlight replaces directional and hemisphere lighting with a camera-mounted soft spotlight, brightest in the centre and fading toward the screen edges. Its cone adapts to projection, zoom, and viewport shape, with brightness independent of model distance. Bearing/clino are disabled in Headlight and restored when returning to a directional mode. Scene visibility, culling, and light choices carry over when opening another file. Click `loch.js` for build information.

The loaded project title appears at the upper left and remains visible with the menu collapsed. Both loaders use the first nonempty LOX survey title, then the survey name or filename if no title is stored. Long titles are shortened visually to fit the screen.

**Indicators** starts enabled under Scene → Visibility and controls the project title, altitude color legend, compass, tilt indicator, and horizontal scale bar together. The compass sits above tilt in the lower left, with the horizontal scale bar beneath them; the color legend stays in the lower right. Indicator panels use translucent backgrounds; bearing runs clockwise from north (+Y), and tilt is 0° horizontal, +90° up, or −90° down. The scale bar follows zoom and projection changes, and uses a rounded metric distance measured in the plane through the camera target for perspective views. Reopening the menu restores the bottom status line; collapsing it hides the line and gives that space back to the model.

**Centreline** has separate Surface, Underground, Splay, and Duplicate toggles, all enabled by default. The Visibility → Centreline checkbox still hides or shows the entire centreline. Color defaults to Altitude; Default uses pure white for ordinary underground and duplicate shots. Surface shots stay gray in either color mode. Splays use half saturation and lower lightness in Altitude mode, and muted gray in Default mode. Duplicate shots otherwise use the same colors as ordinary underground shots. Shots with multiple flags respect each applicable visibility filter; LOX shots marked not visible remain hidden. Both loaders preserve the shot types, and these controls retain their choices when another file is opened.

**Surface** displays terrain grids and their embedded JPEG/PNG map images from the LOX file, positioned using their own world calibrations. It starts visible, with Transparency enabled and Opacity at **50%**, matching [Loch’s defaults](https://github.com/therion/therion/blob/master/loch/lxSetup.cxx). Image overlay starts enabled. Turning it off replaces the map image with a 100% white terrain material shaded by the current scene lights, including Follow camera and Headlight. Turning it back on restores the image without reloading it. The Opacity slider appears when Transparency is enabled; turning transparency off makes the terrain opaque and preserves the slider value. These choices carry over to the next model. Terrain without an embedded image is white, and files without terrain display the cave as before. Terrain is included in the model’s bounding box and initial fit; cave depth colors retain their original cave altitude range. Both file loaders support surfaces, and Automatic detail composites transparent terrain once after the opaque wall batches finish.

**Autorotate** starts off and can be toggled from View or the play/pause button beneath Walker. It turns around the current orbit centre once every **15 seconds**, preserving tilt and distance, with speed measured from elapsed time rather than frame count. Dragging temporarily pauses the automatic turn. Loading/preparing a large file and hidden browser tabs also pause it; rotation resumes afterward. Pausing lets Automatic detail refine the stationary view as usual.

**Walker** starts off and can be toggled from View or the walking-person button beneath the menu button. Left drag looks around from the camera’s position (drag down to look up, drag right to look left), right drag pans, and middle drag / wheel moves forward or backward along the viewing direction. Movement has a fixed speed independent of orbit distance: 10 metres per 100 pixels of middle drag, and 2 metres per 100 wheel delta pixels. Panning uses 5 metres per 100 pixels. On touchscreens, one finger looks around, two-finger dragging pans, and pinching walks forward/backward at the fixed walking scale (spread fingers to move forward). Adding or lifting a finger does not jump the view. Camera tilt remains Z-up; Lock tilt also applies while walking. Both controls stay synchronized, and switching modes preserves the current view.

## Development

Requires Node.js 22+ and npm. `npm install && npm test && npm run dev`. Production site: `npm run build && npm run preview`. Serve the `dist` directory over HTTPS for PWA installation (localhost is also accepted). After first successful load, install the app via your browser and reopen offline.

Desktop: install Rust, platform [Tauri 2 prerequisites](https://v2.tauri.app/start/prerequisites/), and `npm install`. Run `npm run tauri dev`; bundle with `npm run tauri build`. Linux AppImage/DEB requires WebKitGTK 4.1 etc. Windows packages need WebView2 (provided or installed by Windows/installer). macOS builds need Xcode command-line tools.

Desktop builds use their bundled frontend without a PWA service worker. On launch, the native app removes any service workers and cached pages left by older desktop versions and reloads once if needed. Updating or reinstalling therefore recovers from the old desktop PWA cache automatically. Browser and Android PWA builds retain offline caching.

## CI and publishing

`.github/workflows/ci.yml` tests/builds web and the three desktop systems on PRs and pushes. `main` pushes deploy GitHub Pages (enable **Settings → Pages → Source: GitHub Actions**); `v*` tags attach `.exe`, `.msi`, `.deb`, `.AppImage`, `.dmg` release assets. The macOS `.app` is delivered inside the DMG and stored as a workflow artifact. Unsigned desktop binaries may trigger operating-system security prompts. GitHub Pages path is inferred from `GITHUB_REPOSITORY`.

CI identifies builds as `<last-version>-<short-commit>`, using the latest reachable `v*` version tag without its `v` prefix and seven commit characters (for example `0.1-abcdef1`). Before the first version tag, the package version is used. Installer filenames end in that build ID, for example `loch.js_0.1.0_x64-setup_0.1-abcdef1.exe`. Artifact archives are named `desktop-<platform>-<build-id>` and `web-pwa-<build-id>`. Compare the short commit with the About dialog opened by clicking `loch.js`.

## LOX notes and limitations

Parser follows Therion [`loch/lxFile.h`](https://github.com/therion/therion/blob/master/loch/lxFile.h) and [`loch/lxFile.cxx`](https://github.com/therion/therion/blob/master/loch/lxFile.cxx): little-endian 16-byte chunk headers `(type, recordsBytes, count, blobBytes)`; stations (2) with 64-bit XYZ, shots (3), scraps (4) containing indexed 3D points and triangles. Surveys (1), surface terrain (5), and surface imagery (6) are safely skipped; this POC does **not** display surface data, stations/labels or LRUD-generated walls. Centerline excludes surface, hidden and splay shots. Source coordinates are locally recentered for floating-point precision. Smooth shading is calculated from shared indexed vertex normals within each scrap; separate scraps do not share normals, and surfaces with duplicated/non-welded vertices may show seams.

Files larger than 32 MiB use an experimental full-detail loader: a worker reads at most 8 MiB at a time, scans the bounds, and transfers batches of at most 65,536 triangles. It never reads the whole file into one buffer or expands large meshes into JavaScript point/triangle objects. Source triangle order and winding are preserved. Large walls use GPU flat shading and altitude coloring to avoid normal/color arrays; small files retain their existing shading. The bounds and centreline remain visible during loading, with the walls shown after geometry preparation and upload. Status progress continues through geometry preparation and GPU upload with batch percentages, then shows animated indicators for shader compilation and the first wall render. Loading finishes only when that GPU render completes. Opening another file cancels the current load and preparation.

**Rendering → Detail → Automatic** uses shaded point samples and a 262,144-triangle budget while moving. Point normals come from at most 512 sampled faces per batch, with altitude colors and the scene’s hemisphere/directional lighting; no full-mesh normal calculation is needed. After the camera stops, every visible triangle batch is progressively drawn into a cached color/depth image; the moving-preview budget does not limit the finished stationary view. Each batch's GPU buffers are released after drawing, while the full source geometry remains in memory. Moving the camera resets refinement. Loading and refinement show a background progress bar behind the status text. **Full detail** is the default and attempts to draw every triangle directly. `domica-10cm.lox` has 27,647,432 triangles and needs about 949 MiB for positions alone; direct full-detail rendering also needs a GPU copy and can be very slow on software graphics or devices with limited GPU memory.

Generated sample: `python scripts/generate-sample.py` — synthetic geometry in genuine LOX record layout, not a model exported by Therion. Test against actual Therion exports before production. No cross-platform runtime/browser checks, notarization, signing or release publication can be claimed until GitHub runners are executed.

**Reproducibility:** The package-lock could not be generated in the offline build environment. CI currently runs `npm install`; commit a lockfile and change this to `npm ci` once registry access is available.
